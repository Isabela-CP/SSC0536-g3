## 🏗️ Arquitetura e Componentes
✅ **Modelagem 1:1:** O uso de chave primária compartilhada (`id_estabelecimento UUID PRIMARY KEY REFERENCES...`) entre `estabelecimentos` e `meio_hospedagem` é uma excelente prática para garantir integridade referencial e cardinalidade estrita.
✅ **Estratégia de JSONB:** A utilização de `JSONB` para campos de checklists (infraestrutura, acessibilidade) com índices `GIN` e constraints de validação de tipo é a escolha correta para manter a flexibilidade exigida pelo contrato sem sacrificar a performance de busca.
✅ **Soft Delete:** A implementação de inativação lógica via `status` + `inativado_em` + `check` constraint garante a preservação do histórico de dados, essencial para relatórios de auditoria e estatísticas.
✅ **Idempotência:** Os scripts de seed utilizam `ON CONFLICT` corretamente, permitindo que o ambiente de desenvolvimento seja re-povoado sem erros de duplicação.

## 🟡 Não bloqueia
- **Sugestão de Performance:** Como a tabela `estabelecimentos` tende a crescer com o tempo, o uso de `pg_trgm` (trigram index) poderia ser considerado futuramente caso a busca por `nome_fantasia` ou `razao_social` via `LIKE` se torne lenta, permitindo buscas de texto parcial mais performáticas.
