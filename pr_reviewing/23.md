## 🏗️ Arquitetura e Componentes
✅ **Decisões acertadas:**
- **Fonte única da verdade:** A criação do `REVIEW_GUIDE.md` centraliza os critérios de avaliação, facilitando a manutenção e a uniformidade das revisões, seja por humanos ou pela IA.
- **Resiliência:** A implementação de *fallback* entre diferentes modelos de LLM (`gemini`, `openai`, `anthropic`) no script Python (`review_pr.py`) evita que a pipeline de CI se torne um ponto único de falha.
- **Integração CI:** O uso do GitHub CLI (`gh`) dentro do workflow permite uma comunicação fluida e nativa com o ecossistema do repositório, facilitando a busca por metadados de issues.

- **Estratégia de Diff:** O limite de 30k caracteres (`review_pr.py:112`) é adequado agora, mas considere implementar um resumo de arquivos mais relevantes (ex: focar em `.jsx/.tsx`) caso o repositório cresça e ultrapasse esse limite com frequência.
